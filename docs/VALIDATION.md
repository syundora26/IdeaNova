## 別ドメイン化で確認したこと

- 企業の化粧品事業紹介から独立化粧品サイトへ同一タブで移動し、ブラウザの「戻る」で企業紹介へ戻る。
- 企業ヘッダーに会員・カートを表示しない。化粧品ヘッダーの件数は化粧品のみ。企業側ショップは農作物中心、化粧品のフッターに農作物売場・管理入口を置かない。
- 化粧品の旧商品URLで商品IDを保持。旧ログインから購入手続きへの復帰を保持。任意外部URL、プロトコル相対URL、バックスラッシュ、ログインループ等を拒否。
- 化粧品で登録した会員が企業側でも同じ資格でログイン可能。登録だけで他サイトは自動ログインしない。プロフィール更新を共有し、片側ログアウト後も他方の注文確認を継続。
- Cookie名をサイト別に分離し、HttpOnly・SameSite属性を確認。ブラウザ保存にメール・パスワードを残さない。再読込でもCookieから会員・注文を復帰。
- 別事業のカート更新・見積・注文・注文取得・決済開始をサービス側で拒否。履歴はそのサイトの事業のみ。同じ冪等キー文字列でも異事業の注文を混同しない。
- 旧カートの移行案内・現在内容の確認・確定・再読込を確認。元の化粧品保存データを保持。農作物カートを変更しない。
- 10分の移行ID、無効ID、専用シナリオの期限切れIDを検査。移行前の価格・在庫変更は再確認。販売停止品は移行不可。既存新カートの数量と重複加算せず、再適用で削除済み商品を復活させない。
- 共通管理に両事業の注文と会社・化粧品・農作物の3窓口問い合わせを反映。化粧品側の管理RPCを拒否し、企業の担当事業権限と読み取り専用制御を維持。
- 未ログイン時のレビュー本文取得拒否、会員の複数投稿、公開用項目の限定、公開・編集後の公開待ち状態を維持。
- 化粧品紹介割引と農作物適用外、停止・期間外・上限・未承認・商品対象外を維持。
- PayPay失敗・取消・結果不明・照会、銀行入金確認、外部発送の失敗・再連携・追跡・返金調整は単体/共通サービス検証。画面操作では結果不明時に再決済ボタンを出さず照会で解決。
- 購入直前の価格変更と問い合わせ送信失敗で入力保持。専用シナリオ画面を往復して問い合わせ本文を保持し再送成功。
- 管理の記事公開、商品作成、送料変更が独立化粧品の商品に反映、紹介者承認、会員訂正・監査を確認。
- 直接アクセス・再読み込み、農作物ゼロ件、本文スキップ、管理確認ダイアログのTab循環とEscapeを確認。

## 公開用設定とビルド

正式URLなし、localhost、予約テストドメイン、同一ホストの別ポート、認証情報付きURLを公開用ビルドで拒否しました。2つの確認用出力を`dist/corporate`と`dist/cosmetics`へ生成しました。

ビルド表示試験ではPlaywrightでビルド済みHTML/JS/CSS等を各プレビューのオリジンに配信し、APIだけローカルプロキシを使用しました。企業トップ、企業から化粧品への同一タブ遷移、化粧品商品詳細の直接アクセス・再読込、化粧品管理ページ非配置を確認しました。実ホスティング、DNS、TLS、CDNの検証ではありません。

## 制限・未検証

- 実認証、本人確認メール、Fortify/Sanctum設定、実管理者認可、CSRFの本番構成、共通DBの排他・永続保存・監査改変防止は未接続です。デモサービスの成功を本番セキュリティの合格と扱いません。
- ローカルCookieは同じ127.0.0.1ホストの別名Cookieです。正式な別ドメインとHTTPSでのセッション・リバースプロキシ/BFF検証は正式環境の決定後に必要です。
- 共通サービスはメモリ内・直列処理で、再起動により共通データが初期化されます。可用性・負荷・長時間運用・セッションの24時間実待機は検証対象外です。
- 実PayPay、銀行振込、メール、外部発送、正式商品・法務原稿、税/送料/端数処理は未確定です。外部への実送信・実決済はありません。
- axeは自動検査で検出できる項目の結果です。全障害・全支援技術の適合保証ではありません。iOS Safari/Android実機は未検証です。
- 旧ドメインideanova.jpの移行、正式公開、SEO承継は行っていません。
